# 验证样例

这两份报告是在真实环境（MySQL 8.4 + Redis + RocketMQ + MinIO + Qdrant + DashScope）跑出来的产物，用于说明系统在真实素材上的实际表现，而不只是单测里的断言。

| 文件 | 素材 | 说明 |
| --- | --- | --- |
| `sample-report-10min-video.md` | B 站视频，10 分 27 秒，824×480 | 播客式访谈，含大量口语表达与 PPT 画面 |
| `sample-report-3s-text.md` | 自造 3 秒视频，1280×720 | 纯文字画面 + 英文语音，链路最短路径 |

## 值得注意的地方

**长视频那份报告如实记录了「证据不足」**。例如：

> 视频提出架构局限性主张 'Router仅支持飞书群聊/GitHub Issue，无法覆盖私聊'，该主张在 ASR 与 OCR 中均未被字面陈述；[05:00-10:00] 概要提及此点，但 VideoContext 提供的 ASR/OCR 证据中无任何时间点出现 '飞书群聊'、'GitHub Issue'、'私聊' 或等效字面表述。

这是有意设计的行为：宁可明确写出「这条主张没有直接证据」，也不要让它看起来像是被验证过。读者能据此判断哪几条结论可以采信。

**OCR 的乱码被保留原样**。例如 `程序员在未来是一定要上升到决策尾的，只会做 edng的程序员是一定会被光汰的`（原文应为「决策层」「coding」「淘汰」）。报告没有替 OCR 纠错，因为纠错本身就是一次未经授权的推断。

## 采集条件

- 模型：qwen-plus（生成）、qwen3-asr-flash（语音）、text-embedding-v3（向量）
- OCR：Tesseract chi_sim+eng，本地执行
- 证据校验：确定性校验通过。这份报告产出的那一轮模型没有额外提出建议，
  因此没有「模型审阅意见」一节；有建议时该节会自动出现
